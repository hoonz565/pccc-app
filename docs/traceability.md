# Sprint 1 Requirement Traceability

This table covers only the identity and first-Facility vertical slice implemented in Sprint 1. It does not restate future System Design scope.

| Requirement | API | Database / Migration | Backend use case | Flutter flow | Automated tests |
| --- | --- | --- | --- | --- | --- |
| FR-M1.1 — Login by email/password; invalid credentials create no session | `POST /api/v1/auth/login` | `users`, `auth_sessions`; `0001_identity` | `login_user` normalizes email, performs constant-work password verification, and returns one generic 401 | `LoginScreen` → session controller → Facility routing | `test_login_postgres.py`; `login_screen_test.dart`; `app_session_controller_test.dart` |
| FR-M1.2 — Register with explicit terms/privacy consent | `POST /api/v1/auth/register` | Consent versions/timestamps on `users`; unique normalized email; `0001_identity` | `register_user` hashes with Argon2id and handles duplicate races as 409 | `RegisterScreen` requires both `draft-v1` consent checkboxes → first-Facility onboarding | `test_registration_postgres.py`; `test_auth_validation.py`; `register_screen_test.dart` |
| Sprint 1 subset of FR-M1.4 — Create the first Facility and reach Home | `POST /api/v1/facilities` | `facilities`, `audit_events`; `0002_facilities_audit` | `create_facility` commits Facility and `facility_created` audit atomically | `FirstFacilityScreen` → `HomeScreen` | `test_facilities_postgres.py`; `first_facility_screen_test.dart`; `app_session_controller_test.dart` |
| FR-M1.6 — Logout clears local credential/session without deleting server data | Bearer-authenticated `POST /api/v1/auth/logout` | `auth_sessions.revoked_at`; stable `AuthSession.id`; `0001_identity` | `logout_session` idempotently locks and revokes JWT `sid`; refresh/logout serialize on the same row | Home `Đăng xuất` → exclude/settle refresh → delete secure credential → clear in-memory token → best-effort revoke → Login; deletion failure remains recoverable | `test_logout_postgres.py`; `app_session_controller_test.dart` |
| FR-M2.1 — Create Facility with required name, type, province, and address | `POST /api/v1/facilities` | Owner-scoped Facility, revision `1`; `0002_facilities_audit` | Owner comes only from authenticated principal; strict request schema rejects spoof fields | Required onboarding form; Facility type remains free text | `test_facilities_postgres.py`; `first_facility_screen_test.dart` |
| System Design authentication control — expiry, refresh, revoke | `POST /api/v1/auth/refresh`; `POST /api/v1/auth/logout`; `GET /api/v1/me` | Hashed rotating refresh token, stable session ID, expiry, revocation, refresh timestamp | Row-locked rotation/revocation; JWT `sub`/`sid` validation against active session for protected endpoints | Cold start restores through secure refresh → `/me` → Facility list | `test_refresh_postgres.py`; `test_logout_postgres.py`; `test_security.py`; `app_session_controller_test.dart`; `auth_token_manager_test.dart` |
| System Design authorization control — server-side Facility ownership | `GET /api/v1/facilities`; `POST /api/v1/facilities` | `facilities.user_id` FK and owner index | Every Facility query derives owner from authenticated principal | UI never supplies an owner identifier | `test_facilities_postgres.py` ownership, spoofing, and unauthenticated cases |

The scan/skip portion of FR-M1.4, Area CRUD, Facility edit, aggregate counts, and Facility selector are not represented as completed rows because they are deferred beyond this Sprint 1 slice.
